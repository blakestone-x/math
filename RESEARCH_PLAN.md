## How the fleet runs a target

1. Locate the original statement, including quantifiers, index conventions, hypotheses, known cases and an exact source revision when available. Check both the project index and independent literature before assigning credit.
2. Send one lane after a proof and another after counterexamples when the target admits both. Keep early experiments separate from release manuscripts. Record a failed route if it rules out a proposed argument.
3. Ask a second reader to reconstruct the critical lemma, test boundary cases and compare the final theorem with the source. For computational proofs, publish the finite reduction, exhaustive coverage argument, executable verifier and expected output. Label what Lean checks when a formalization is available.
4. Publish each accepted package on GitHub with an editable manuscript and reading copy. Add one row per research package and link related conjectures from that row. Distinguish full resolutions, partial results, deductions from prior work and independently verified computations. Preserve concurrent commits when updating the index.
